# Recovery message attribution

Interruption evidence generated by the harness enters the loop as
`RecoveryMessage`, separately from `UserMessage`. This applies to cancelled
turns, interrupted submissions, and recovered tool batches. Text matching is
never used to change a message's author.

Canonical history stores recovery as assistant `output_text` with the local
`haskell-agent.recovery-context` content kind. The marker survives JSON
persistence and resume. Transcript views, activity previews, and voice answers
exclude these messages; interruption policy does not treat them as model
output.

Provider projections preserve their native contracts:

| Provider | Recovery projection |
| --- | --- |
| OpenAI HTTP and WebSocket | Assistant `output_text`; local metadata removed |
| xAI and OpenRouter Responses | Assistant `output_text`; local marker removed |
| Gemini | Native `model` text |
| Claude SDK | Quoted text labelled as harness recovery context in its prompt input |

Older persisted messages keep their existing roles. A user quoting
`<turn_aborted>` remains a user message. Recovery text also counts against the
pending input byte limit.

Regression coverage exercises core interruption recovery, canonical JSON
round trips, provider request projection, runtime cancellation, and transcript
hydration through the corresponding Cabal test components under `nix develop`.
